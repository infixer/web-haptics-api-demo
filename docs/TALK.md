# 10 分 LT 進行台本

**タイトル案:** 「震えるウェブ — Web Haptics API と、モールス信号が打てない話」

**主張（これだけ持ち帰ってもらう）:**
> Web Haptics API は「触覚の波形」ではなく「触覚の**意味**」を送る API である。
> だから表現力が意図的に絞られている。その境界は、踏み抜いてみて初めて分かる。

## 0:45–2:15 いまの Web の触覚は貧しい

```js
navigator.vibrate([100, 100, 300]);  // これだけ
```

3 点を、それぞれ実演を挟みながら:

1. **iOS Safari は対応していない。** ずっと。今も。
   → 会場の iPhone ユーザーに「今、震えなかった人？」と手を挙げてもらうと効く
2. **デスクトップには存在しない。** MacBook のトラックパッドは触覚デバイスなのに、Web からは触れない
3. **低レベルすぎる。** `[100, 100, 300]` が何を意味するかコードから分からない。
   端末ごとにモーター特性が違うので、**開発者が端末ごとに手でチューニングする羽目になる**

> 「つまり、`vibrate` は “振動子を何ミリ秒回すか” という**ハードウェアの都合**の API なんです。
> これは Web の他の API の作り方と、明らかに違う。」

## 2:15–4:15 Web Haptics API とは

**設計思想の転換を 1 枚で:**

```
navigator.vibrate([100, 100, 300])   ← どう振動させるか（HOW）
navigator.playHaptics("align", 0.8)  ← 何を伝えたいか（WHAT）
```

**エフェクトは 4 つだけ:**

| effect | 意味 |
|---|---|
| `hint` | 触れられる、何か起きそう |
| `tick` | 離散的な変化（リスト送り、トグル） |
| `align` | ピタッとはまった |
| `edge` | 端に当たった、これ以上は無い |

**「たった 4 つ？」と思うところで、正の例をデモする（#1 スライダー）。**

> （スライダーをドラッグしながら）
> 「刻みで `tick`、真ん中で `align`、端で `edge`。
> ……**これ、全部 CSS で書けます。**」

```css
button:active {
  scale: 0.95;
  @haptic align 0.8;
}
```

**そして、この API の一番面白い決定を紹介する:**

```js
navigator.playHaptics("tick");  // → undefined
```

> 「**必ず undefined を返します。**
> 効いたかどうかも、そもそも対応しているかも、一切分かりません。
> フィンガープリンティングを防ぐために、**意図的に何も教えない**設計です。
> 後でこれが効いてきます。」

## 4:15–7:00 【本題】モールスを実装したら壁にぶつかった

**ここが山場。時間配分の 1/4 をここに使う。**

### ステップ 1: モールスの定義を出す（30 秒）

```
短点 = 1 単位 ON
長点 = 3 単位 ON     ← 「3 倍の長さ」が情報の本体
```

> 「モールスは**持続時間で情報を運ぶ言語**です。」

### ステップ 2: `playHaptics` で書こうとして詰まる（1 分）

```js
// 短点を打ちたい
navigator.playHaptics("tick");
// 長点を打ちたい
navigator.playHaptics("edge");   // ← これ、どれくらいの長さ？
```

> 「……**指定できないんです。** duration という引数が無い。
> `edge` がどれくらい振動するかは OS が決めます。
> つまり、**この API でモールスは打てません。**」

### ステップ 3: `/lab` で 3 つを聴き比べ（2 分・**このデモが全て**）

同じ `SOS` を 3 通りで再生する。**Simulator の可聴化で会場にも聞こえるようにしておく。**

```
A  navigator.vibrate    [exact]        ███  ███  ███ …  ← 本物のモールス
B  iOS tick train       [envelope]     ┃┃┃  ┃┃┃  ┃┃┃ …  ← 長さは残る、質感が違う
C  navigator.playHaptics[onset-only]   │    │    │   …  ← リズムだけ、長さが無い
```

> 「C は**モールスではありません。モールスのリズムです。**
> 短点と長点の区別が消えているので、情報としては壊れています。」

### ステップ 4: 落とし所（1 分半）

> 「で、これは **API のバグじゃないんです。**
>
> Web Haptics API は **UI のフィードバック**のための API であって、
> **触覚チャネルでデータを送る**ための API ではない。
> さっきのスライダーには完璧に効いた。モールスには効かない。**それだけの話です。**
>
> ……ただ、これを実際に作ってみるまで、僕はこの境界が見えていませんでした。
> **API の設計思想は、境界を踏み抜いたときに一番はっきり見える。**」

**（時間があれば #2 呼吸ガイドに 20 秒だけ触れて「構造的な限界である」ことを補強）**

## 7:00–8:30 ポリフィルの中身

### 7.1 使い方は 1 行

```ts
import "web-haptics-polyfill";   // ← これだけ

navigator.playHaptics("tick", 0.6);   // 以降は標準 API しか呼ばない
```

> 「**ブラウザが実装した日に、この import を消すだけで移行完了です。**
> ポリフィルの正しい形はこれです。便利な独自 API を生やしたら負け。」

### 7.2 中で何をやっているか（ネタが 2 つある）

**ネタ 1: intensity は PWM で作る**

```
navigator.vibrate に「強さ」は無い
→ 20ms フレームの ON/OFF デューティ比で作る
   intensity 0.5 → [10,10, 10,10, 10,10, ...]
```

**ネタ 2: iOS で触覚を出す唯一の方法**

```html
<label><input type="checkbox" switch></label>
```

```js
label.click();   // ← iOS 17.4+ でこれが本物の触覚 tick になる
```

> 「iOS には `vibrate` が無い。でも **switch をトグルすると震える。**
> なので**非表示の switch を JS で連打する**、という力技です。
> web-haptics ライブラリも同じことをやっています。
>
> ただしこれ、**tick が 1 発出るだけ**なんですね。**“長い振動” は作れない。**
> だから iOS では長点を “tick の連打” で塗りつぶすしかない。
> ……さっき見た B のパターンは、これです。」

### 7.3 CSS はポリフィルできない（正直に言う）

> 「`@haptic` は**未知の at-rule なので CSSOM が捨てます。** JS からは見えない。
> 苦し紛れにカスタムプロパティに載せる手はあります。」

```css
button:active { --haptic: tick 0.8; }   /* これなら getComputedStyle で読める */
```

> 「でも `:hover` や `:active` は拾えても、`:has()` やコンテナクエリは無理です。
> **CSS の機能は、やっぱりブラウザが実装しないとダメなんです。**」

## 8:30–10:00 まとめ

**スライド 1 枚:**

```
Web Haptics API は「触覚の意味」を送る API

  ✅ 向いている  UI のフィードバック（スライダー、トグル、境界）
  ❌ 向かない    データ伝送（モールス）、長い持続（呼吸ガイド）

  navigator.playHaptics() は undefined を返す
   → 対応判定ができない
   → アプリは「ユーザーに聞く」しかない
   → プライバシー設計が UX を規定した
```

> 「最後に一番好きな皮肉を。
> **duration を指定できる標準の触覚 API、実はもう 1 つあります。**
> Gamepad API です。」

```js
gamepad.vibrationActuator.playEffect("dual-rumble", {
  duration: 300, strongMagnitude: 1.0,
});
```

> 「**ゲームパッドでなら、ブラウザでモールスが打てます。**
> つまり Web Haptics API は、**できたはずのことを意図的に捨てている。**
> そこに設計判断がある、という話でした。」
