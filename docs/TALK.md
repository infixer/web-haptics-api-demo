# 10 分 LT 進行台本

**タイトル案:** 「4 つしかない触覚 — Web Haptics API を触ってみる」

**主張（これだけ持ち帰ってもらう）:**
> Web Haptics API は触覚の「波形」ではなく「意味」を送る API。
> エフェクトが 4 つしかないのは機能不足ではなく、**人間がそれ以上見分けられないから**であり、
> 端末差を吸収するための設計判断でもある。

デモページ: `apps/web`（スライダー + 触覚あてゲーム + セットアップ + モニタ）

## 1:00–2:30 いまの Web の触覚はひどい

```js
navigator.vibrate([100, 100, 300]);  // 20 年これだけ
```

MDN の互換データを読むと、想像よりひどい:

| ブラウザ | 状態 |
|---|---|
| Chrome / Edge | 32+ ○ |
| Chrome Android | 60 以降 user gesture 必須、**55 以降クロスオリジン iframe で不可** |
| Safari / iOS | **一度も実装されていない** |
| Firefox | 16 で追加 → **129 で削除**（2024/8） |
| Firefox Android | 79+ は**「`true` を返すが何も起きない」** |

**強調する 2 点:**

1. **エンジンとしては Blink しか残っていない。** Gecko は削除、WebKit は未実装。
2. **特徴検出が嘘をつく。** Firefox Android は `typeof navigator.vibrate === "function"` も
   戻り値 `true` も通るのに、モーターは動かない。

> 「つまり `vibrate` は “モーターを何ミリ秒回すか” という**ハードウェアの都合**の API で、
> しかも**もう誰も真面目に実装していない。**」

## 2:30–4:30 Web Haptics API とは → スライダーを触る

**設計思想の転換を 1 枚で:**

```
navigator.vibrate([100, 100, 300])   ← どう振動させるか（HOW）
navigator.playHaptics("align", 0.8)  ← 何を伝えたいか（WHAT）
```

**エフェクトは 4 つだけ:**

| effect | 意味 |
|---|---|
| `hint` | 触れる、何か起きそう |
| `tick` | 離散的な変化（リスト送り、トグル） |
| `align` | ピタッとはまった |
| `edge` | 端に当たった、これ以上ない |

**「たった 4 つ？」と言われたところでスライダーを触ってもらう。**

> （スライダーをドラッグしながら）
> 「刻みで `tick`、真ん中で `align`、端で `edge`、つまみに触れたら `hint`。
> ……4 つで足りていませんか？」

**そして、つまみのホバーだけは CSS で書いてあることを見せる:**

```css
input[type="range"] {
  --haptic-hover: hint 0.3;      /* 提案では @haptic hint 0.3; */
  --haptic-active: tick 0.6;
}
```

> 「**状態の変化は CSS、ランタイムの計算は JS。**
> 提案が API を 2 つに分けているのは、この住み分けのためです。」

**最後にこの API の一番面白い決定:**

```js
navigator.playHaptics("tick");  // → undefined
```

> 「**必ず undefined。** 効いたかも、対応しているかも、一切分かりません。
> フィンガープリンティングを防ぐために、**意図的に何も教えない**設計です。」

（セットアップ欄を開いて）

> 「なので、このページは**あなたに聞く**しかない。
> 『感じましたか？ はい / 弱い / 何も感じない』。
> **プライバシーのための決定が、UI の形を決めてしまった**わけです。」

## 4:30–6:30 4 つで語彙を作る → 神経衰弱

> 「4 つのエフェクトは、**組み合わせると語彙になります。**」

（パターン一覧を開いて 6 つ鳴らす）

```
タップ   •      tick
ダブル   • •    tick → tick
トリプル • • •  tick → tick → tick
ドン     ●      edge
ノック   ● ●    edge → edge
スウェル · • ●  hint → tick → align
```

> 「神経衰弱をやってみてください。画面には何も出ません。**感触だけです。**」

（会場に 1 分やらせる）

**そのあとで種明かし:**

> 「このパターン、**どのエフェクトを使うかより、回数とリズムで見分けられるように**
> 作ってあります。理由があります。
>
> **iOS では `hint` と `tick` と `align` が、まったく同じ感触に潰れるからです。**
> なぜ潰れるかは次のパートで。」

## 6:30–8:30 ポリフィルの中身

### 使い方は 1 行

```ts
import "@infixer/polyfill-web-haptics-api";

navigator.playHaptics("tick", 0.6);
```

> 「**ブラウザが実装した日に、この import を消すだけで移行完了。**
> ポリフィルの正しい形はこれです。便利な独自 API を生やしたら負け。」

### 中で何が起きているか

```
1. navigator.vibrate + PWM        → Android Chrome
2. <input switch> を click        → iOS Safari 17.4+
3. Gamepad の playEffect          → デスクトップ + コントローラ
4. WebAudio のクリック音（任意）  → 開発・登壇用
```

**ネタ 1: 強さは PWM で作る**

```
vibrate に「強さ」は無い
→ 20ms フレームの ON/OFF デューティ比で作る
```

**ネタ 2: iOS で触覚を出す唯一の方法**

```html
<label><input type="checkbox" switch></label>
```

```js
label.click();   // ← iOS 17.4+ でこれが本物の触覚になる
```

> 「iOS に `vibrate` は無い。でも**スイッチをトグルすると震える。**
> なので**非表示のスイッチを JS で叩く**、という力技です。
>
> ただしこれ、**固定の 1 タップ**なんですね。長さも強さも無い。
> だから `hint` も `tick` も `align` も**全部おなじ**になる。
> ……さっきの神経衰弱がリズムで作ってあった理由がこれです。」

### ネタ 3: 人は本当に間違える（実話）

> 「2026 年 3 月、MDN の互換データに issue が立ちました。
> **『navigator.vibrate、iOS Safari で動きます』**
> テスト方法は『デモサイトを iPhone で開いて、振動を確認した』。
>
> ……**動いていません。** 感じたのは、そのサイトの switch ハックの方です。
> issue はデータを変えずにクローズされました。
>
> **『振動を感じた』と『Vibration API が動いている』は別物で、
> しかも人は MDN に issue を立てるレベルで間違える。**
> だから “ユーザーに聞く” しか無いんです。」

### CSS はポリフィルできない（正直に言う）

> 「`@haptic` は**未知の at-rule なので CSSOM が捨てます。** JS から見えない。
> なのでカスタムプロパティに逃がしました。」

```css
button { --haptic-active: align 0.8; }   /* getComputedStyle で読める */
```

> 「しかも**状態をセレクタから property 名に移して**います。
> 提案は『ルールがマッチし始めた瞬間』に発火しますが、
> **それを知る汎用的なイベントが無い。**
> `pointerdown` で読んで `:active` がもう当たっていることを祈る、では競合します。
>
> 結果、拾えるのは hover / active / focus / checked の 4 つだけ。
> `:has()` もコンテナクエリも無理です。
> **CSS の機能は、やっぱりエンジンが実装しないとダメなんです。**」

## 8:30–10:00 境界とまとめ

### この API で作れないもの

> 「最初、**モールス信号**のアプリを作ろうとしていました。作れませんでした。」

```
短点 = 1 単位 ON
長点 = 3 単位 ON     ← 「3 倍の長さ」が情報の本体
```

```js
navigator.playHaptics("edge");   // ← 何ミリ秒？ 指定できない
```

> 「**duration という引数が無い。** `edge` がどれだけ震えるかは OS が決めます。
> モールスは持続時間で情報を運ぶ言語なので、**この API では原理的に打てない。**
>
> でもこれ、バグじゃないんです。
> Web Haptics API は **UI のフィードバック**のための API であって、
> **触覚チャネルでデータを送る**ための API ではない。
> さっきのスライダーには完璧に効いた。モールスには効かない。それだけの話です。」

### まとめスライド

```
Web Haptics API は「触覚の意味」を送る API

  ✅ 向く    UI のフィードバック（スライダー、トグル、境界）
  ❌ 向かない データ伝送（モールス）、長い持続（呼吸ガイド）

  エフェクトが 4 つなのは、人間がそれ以上見分けられないから
  undefined を返すのは、指紋採取を防ぐため
   → 対応判定ができない → ユーザーに聞くしかない
```

### 最後の皮肉

> 「duration を指定できる標準の触覚 API、実はもう 1 つあります。**Gamepad API** です。」

```js
gamepad.vibrationActuator.playEffect("dual-rumble", {
  duration: 300, strongMagnitude: 1.0,
});
```

> 「ゲームパッドを繋げば、ブラウザでモールスが打てます。デスクトップでも。
> つまり Web Haptics API は、**できたはずのことを意図的に捨てている。**
> そこに設計判断がある、という話でした。」
